# Tacview Integration - Project Overview

## Executive Summary

This document outlines the comprehensive plan for integrating AeroDebrief's audio communication system with Tacview's mission replay software, enabling synchronized voice communications during mission review.

## Project Goals

### Primary Objectives
1. **Bidirectional Synchronization**: Synchronize playback time between Tacview (master) and AeroDebrief (slave) with 1-second precision
2. **Pilot-Filtered Audio**: Filter and play only frequencies relevant to selected pilots in Tacview
3. **Spatial Audio**: Pan each pilot's audio to different ears for clear identification
4. **Visual Feedback**: Display connection health and synchronization status in AeroDebrief
5. **Real-time Indicators**: Show speaking pilots in Tacview with visual highlights
6. **Long-Duration Stability**: Maintain perfect synchronization for 2+ hour recordings

### Success Criteria
- ? **Timing Precision**: ±1 second synchronization accuracy
- ? **Stability**: 2+ hours continuous operation without drift
- ? **Responsiveness**: <100ms latency for Tacview actions
- ? **Reliability**: Seamless data transfer with automatic reconnection
- ? **User Experience**: Clear visual feedback for all states

## Key Components

### 1. Tacview Lua Addon (`TacviewAddon.lua`)
- TCP server running inside Tacview
- Broadcasts mission state changes
- Receives speaking notifications from AeroDebrief
- Updates pilot visual indicators

### 2. Integration Layer (`AeroDebrief.Integrations`)
- **TacviewClient**: TCP client for communication
- **TacviewSyncService**: Synchronization logic and time management
- **TacviewProtocol**: JSON message serialization/deserialization
- **PilotMapper**: Maps Tacview pilot IDs to AeroDebrief frequencies

### 3. UI Layer (`AeroDebrief.UI`)
- **TacviewIntegrationViewModel**: MVVM view model
- **TacviewStatusControl**: Visual status indicator
- Integration with `UnifiedPlayerViewModel`

### 4. Core Enhancements (`AeroDebrief.Core`)
- External time synchronization in `PlaybackController`
- Enhanced pilot filtering in `FrequencyChannelMixer`
- Spatial audio (pan) in `AudioOutputEngine`

## Communication Protocol

### Message Types (Tacview ? AeroDebrief)

```json
{
  "type": "time_update",
  "mission_time_utc": "2024-01-15T14:30:45.123Z",
  "playback_state": "playing",
  "playback_speed": 1.0
}

{
  "type": "pilot_selection",
  "selected_pilots": [
    {
      "pilot_id": "F-16C-001",
      "coalition": "blue",
      "frequencies": [251.0, 305.0],
      "pan": -0.8
    },
    {
      "pilot_id": "F-16C-002",
      "coalition": "blue",
      "frequencies": [251.0, 127.5],
      "pan": 0.8
    }
  ]
}

{
  "type": "playback_command",
  "command": "play" | "pause" | "stop"
}

{
  "type": "seek",
  "target_time_utc": "2024-01-15T14:35:00.000Z"
}
```

### Message Types (AeroDebrief ? Tacview)

```json
{
  "type": "speaking_status",
  "pilot_id": "F-16C-001",
  "is_speaking": true,
  "frequency": 251.0
}

{
  "type": "sync_status",
  "connected": true,
  "sync_drift_ms": 150,
  "current_time_utc": "2024-01-15T14:30:45.273Z"
}

{
  "type": "ready",
  "recording_start_utc": "2024-01-15T14:00:00.000Z",
  "recording_duration_seconds": 7200
}

{
  "type": "frequency_filter_update",
  "pilot_id": "F-16C-001",  // null for general frequencies
  "enabled_frequencies": [251.0, 305.0]
}

{
  "type": "pan_configuration",
  "pan_mode": "manual",  // "auto" or "manual"
  "pilot_pan_settings": {
    "F-16C-001": -0.8,
    "F-16C-002": 0.8
  }
}
```

**Bidirectional Configuration Messages**:

These messages allow AeroDebrief to send configuration updates back to Tacview, enabling UI-driven changes to propagate to the Lua addon.

| Message Type | Direction | Purpose |
|--------------|-----------|---------|
| `frequency_filter_update` | AeroDebrief ? Tacview | Update enabled frequencies for a pilot or general |
| `pan_configuration` | AeroDebrief ? Tacview | Update pan mode and per-pilot pan values |

**Usage Scenarios**:
- User changes frequency checkboxes in AeroDebrief UI
- User adjusts pan slider in AeroDebrief UI
- User switches between Auto/Manual pan modes in AeroDebrief UI

**Tacview Response**:
- Updates internal state (pan_manager.lua)
- Saves configuration to config file
- Broadcasts updated `pilot_selection` message to reflect changes

## Time Synchronization Strategy

### UTC Time as Single Source of Truth
- All systems use UTC timestamps
- Tacview provides mission time in UTC
- AeroDebrief recording has UTC start time
- No timezone conversions or offsets

### Synchronization Algorithm
```
Every 100ms (10 Hz from Tacview):
  1. Receive UTC time from Tacview
  2. Convert to TimeSpan offset from recording start
  3. Calculate drift: |AeroDebrief.CurrentTime - TacviewTime|
  4. If drift > 500ms:
     - Immediate seek to Tacview time
  5. Else if drift > 100ms:
     - Gradual speed adjustment (0.98x - 1.02x)
  6. Else:
     - Normal playback (1.0x speed)
```

### Drift Compensation
- **Small drift (<100ms)**: Speed adjustment
- **Medium drift (100-500ms)**: Quick catch-up
- **Large drift (>500ms)**: Immediate seek

## Pilot Filtering & Spatial Audio

### Frequency Mapping
```csharp
// Tacview provides pilot ? frequencies mapping
// AeroDebrief filters packets by:
//   1. Is transmitter one of selected pilots?
//   2. Is frequency in pilot's frequency list?

// Example:
Pilot "Viper-1" on frequencies [251.0, 305.0]
? Play all packets where:
    - TransmitterGuid == "Viper-1-GUID"
    - Frequency in {251.0, 305.0}
```

### Spatial Audio (Pan)
```csharp
// Tacview provides pan value per pilot (-1.0 to +1.0)
// -1.0 = Full left ear
//  0.0 = Center
// +1.0 = Full right ear

// AeroDebrief applies pan to audio output:
leftGain = (1.0 - pan) / 2.0;
rightGain = (1.0 + pan) / 2.0;
```

## Connection Management

### States
1. **Disconnected**: No connection to Tacview
2. **Connecting**: Attempting TCP connection
3. **Connected**: TCP established, handshake pending
4. **Synchronized**: Fully operational
5. **Degraded**: Connected but high drift/errors

### Auto-Reconnection
- Retry every 5 seconds if disconnected
- Exponential backoff for repeated failures
- Maximum 30-second backoff interval

### Health Monitoring
- Track sync drift over time
- Measure message latency
- Count dropped messages
- Display health metrics in UI
