# Quick Start: End-to-End Pipeline Tests

## TL;DR

```bash
# Run all end-to-end tests
dotnet test --filter "TestCategory=EndToEnd"
```

That's it! Tests generate their own dummy data and validate the entire pipeline.

## What Do These Tests Do?

1. **Generate** a synthetic recording file (.adb)
2. **Read** and validate packet structure
3. **Analyze** frequencies, duration, and activity
4. **Decode** audio and validate quality
5. **Index** file using memory-mapped I/O
6. **Playback** audio through complete pipeline
7. **Validate** audio quality with metrics

All using **dummy data generated by the test system** - no external files needed!

## Run in Visual Studio

1. Open **Test Explorer** (`Test ? Test Explorer`)
2. Type `TestCategory=EndToEnd` in the search box
3. Click **Run All Tests**

## Run in Command Line

```bash
# All tests
dotnet test --filter "TestCategory=EndToEnd"

# With detailed logging
dotnet test --filter "TestCategory=EndToEnd" --logger "console;verbosity=detailed"

# Specific test
dotnet test --filter "FullyQualifiedName~GenerateRecording_CreatesValidFile"
```

## View Results in GitHub Actions

1. Go to your repository on GitHub
2. Click **Actions** tab
3. Click **"End-to-End Pipeline Tests"** workflow
4. View results for Windows, Linux, and macOS

## Troubleshooting

### "Build failed"
```bash
dotnet clean
dotnet build
```

### "Tests taking too long"
- Normal: Stress test (Test 10) can take 30-45 seconds
- Generating 10MB recording + full analysis + playback

### "Test failed"
- Check test output for specific error
- Verify disk space for temp files
- Check audio drivers (for playback tests)

## Files Created by Tests

Tests create temporary files in `%TEMP%`:
- `synthetic_*.adb` - Recording files
- Automatically cleaned up after each test
