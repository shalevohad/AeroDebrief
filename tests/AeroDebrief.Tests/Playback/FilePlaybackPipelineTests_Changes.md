# FilePlaybackPipelineTests - Mock Data Migration

## Summary
Updated `FilePlaybackPipelineTests` to use mock data generated by `MockRecordingFileBuilder` instead of relying on external test files. This makes the tests self-contained, faster, and more reliable.

## Key Changes

### 1. **Removed External File Dependency**
- **Before**: Tests looked for test files in multiple locations (`TestData\sample.srs`, `C:\Temp\test.srs`, etc.)
- **After**: Tests generate mock recording files on-the-fly using `MockRecordingFileBuilder`

### 2. **Setup and Cleanup**
- Added `[TestCleanup]` to automatically delete temporary test files after each test
- `Setup()` now calls `CreateMockRecordingFile()` which uses `MockRecordingFileBuilder.CreateConversationTestFile()`

### 3. **New Test Cases**
Added two new test methods to verify multi-frequency and player information:
- `GetAvailableFrequencies_WithMultipleFrequencies_ReturnsAll()`: Uses `CreateMultiFrequencyTestFile()` to test multiple frequencies
- `GetAvailableFrequencies_IncludesPlayerInformation()`: Verifies player metadata is correctly populated

### 4. **Removed Inconclusive Tests**
- Tests no longer become inconclusive when external files are missing
- All tests now run reliably with generated mock data

## Benefits

### ? **Reliability**
- Tests always have data available (no missing file errors)
- Consistent test data across all environments

### ? **Speed**
- Mock files are smaller (10 seconds vs potentially large recordings)
- No need to commit large test files to repository

### ? **Maintainability**
- Test data is defined in code, easy to understand and modify
- Can create specific scenarios for edge case testing

### ? **Isolation**
- Each test gets a fresh mock file
- No risk of external files being modified or corrupted

## Mock Data Used

### Primary Test File (CreateConversationTestFile)
- Duration: 10 seconds
- Players: "Viper-1" and "Viper-2"
- Frequency: 251.0 MHz (UHF)
- Pattern: Alternating transmissions with silence gaps

### Multi-Frequency Test File (CreateMultiFrequencyTestFile)
- 3 frequencies:
  - 251.0 MHz (UHF, Blue coalition, "Viper-1")
  - 127.5 MHz (VHF, Red coalition, "Enfield-1")
  - 305.0 MHz (UHF, Blue coalition, "Overlord")
- 20 packets per transmitter

## Future Enhancements

While this update uses `MockRecordingFileBuilder` for file generation, the tests still use the real `AudioOutputEngine` and `AudioProcessingEngine`. For even faster unit tests, consider:

1. Creating a mock version of `FilePlaybackPipeline` that uses:
   - `MockAudioOutputEngine` instead of `AudioOutputEngine`
   - `MockAudioProcessingEngine` instead of `AudioProcessingEngine`

2. This would eliminate audio hardware dependencies and make tests run even faster

3. However, current tests serve as integration tests, which is valuable for verifying the full pipeline works correctly

## Running the Tests

All tests should now run successfully without any external dependencies:

```bash
dotnet test --filter "FullyQualifiedName~FilePlaybackPipelineTests"
```

No setup or test data preparation required!
